# QualityMate 발표자 노트

## 슬라이드 1

발표는 현재 구현하고 검증한 범위를 기준으로 구성했습니다. 가상 검사 데이터와 시연용 작업표준서를 사용합니다. 개인 프로젝트 기준이며 실제 제출자 정보와 역할은 제출 시 본인이 확인합니다. 표지의 코드 배경은 InspectionStore.cs에서 발췌했습니다.

## 슬라이드 2

가상 제조 검사 업무를 대상으로 했습니다. 실제 생산성 향상이나 현장 도입 성과는 측정하지 않았습니다. 사용자는 검사 담당자와 품질 담당자로 설정했습니다.

## 슬라이드 3

시연용 기본 제품 3개를 제공하며 VisionQC CSV 샘플 3개를 추가로 가져올 수 있습니다. 실시간 카메라 추론, 문서 업로드, 사용자 권한 기능은 범위에 포함하지 않았습니다.

## 슬라이드 4

브라우저가 ASP.NET Core API에 요청합니다. API는 SQLite에서 검사 사실을 읽고 JSON 표준서에서 관련 절을 검색합니다. Ollama의 kanana2:3b가 근거 문장 번호를 선택하고 서버가 해당 원문과 인용을 반환합니다. 자료는 Program.cs, InspectionStore.cs, knowledge/standards.json입니다.

## 슬라이드 5

Inspections는 제품 ID, LOT, 최초 판정, 관찰, 검사 시각을 저장합니다. Reinspections는 최초 검사를 외래키로 참조합니다. 최초 판정은 변경하지 않고 최신 판정은 마지막 재검사에서 계산합니다. 기존 JSON 파일이 있으면 최초 DB 생성 시 이관하며 원본 파일은 보존합니다. 출처 InspectionStore.cs.

## 슬라이드 6

소형 모델이 원문을 반복하거나 무관한 문장을 선택하는 문제가 있었습니다. 키워드 검색과 문장 정렬을 적용하고 JSON Schema로 출력 형식을 제한했습니다. 서버는 후보에 있는 원문만 출력합니다. 자유로운 요약 대신 근거 선택형 답변을 제공하며 표현력과 복합 질문 완전성에는 한계가 있습니다. AI 연결 실패 시 검색 원문을 표시합니다. 출처 Program.cs.

## 슬라이드 7

실제 로컬 실행 화면입니다. 샘플 CSV 3개를 가져온 후 제품 6개와 재검사 1개를 확인했습니다. 모든 데이터는 시연용입니다. UI에서 최초 불합격과 현재 합격을 함께 확인했고 로컬 AI 답변을 확인했습니다. 파일 선택창 자동화는 중단됐으며 가져오기 API와 원본 exporter 생성 파일의 호환성을 별도로 검증했습니다.

## 슬라이드 8

VisionQC.Core/InspectionCsv.cs 원본 코드를 링크한 별도 시연 프로그램으로 가상 행 3개를 내보냈습니다. 실제 exporter의 따옴표 CSV를 파싱하고 3개가 추가되는 것을 확인했습니다. CSV의 Id와 JobId로 VQC-작업ID-검사ID를 구성합니다. 실시간 카메라나 실제 추론 정확도 검증은 수행하지 않았습니다. 원본 exporter SHA256 FB7D220047EF6A2919FB5815D7170C6358D67A65EDC77BB205D59F981066654C.

## 슬라이드 9

기능 검사 17개가 통과했습니다. RAG 평가는 도메인 질문 16개와 무관한 질문 4개입니다. 관련 절 검색, 실제 LLM 동작, 인용 표시, 출처 원문 일치와 필수 구절 포함을 확인했습니다. 20/20은 이 고정 세트에 대한 결과이며 일반적인 현장 정확도를 의미하지 않습니다. 출처 submission/evidence/functional-checks.txt, rag-evaluation.json, tools/questions.json.

## 슬라이드 10

2026-11-19 최종 측정입니다. LLM 호출 질문 16개 중앙값 2982ms, 무관한 질문 4개를 포함한 전체 20개 중앙값 2782.5ms, 최대 4031ms입니다. 같은 PC의 로컬 실행이며 워밍업, 동시 작업, 하드웨어에 따라 달라집니다. 비교 실험이나 현장 처리량을 측정한 수치가 아닙니다. 출처 rag-summary.json.

## 슬라이드 11

시연은 4~5분으로 준비합니다. 기본 QM-001을 선택하고 재검사 기록 질문을 합니다. AI 근거 선택과 SOP-03을 확인합니다. 시연 검사자와 메모를 입력해 저장한 뒤 최초 FAIL과 현재 PASS가 함께 남는 것을 확인합니다. 샘플 CSV를 가져오고 ERROR가 검사 오류로 유지되는 것을 확인합니다. 이미 가져온 파일은 중복 제외됩니다.

## 슬라이드 12

현재 SQLite를 사용합니다. 초기 SQL Server 계획은 설치 없는 제출용 실행을 위해 SQLite로 조정했습니다. 외부 공개용 로그인과 권한 제어, 사용자 문서 업로드 기능은 구현하지 않았습니다. Ollama와 kanana2:3b 모델은 별도 설치가 필요하며 모델 가중치를 제출 패키지에 포함하지 않습니다. 실제 기기와 사용자 검증을 거쳐 현장 적용 범위를 정해야 합니다.
