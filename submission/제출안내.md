# QualityMate 제출 패키지
작성 기준 2026-11-20. 사용자 확인에 따라 개인 프로젝트로 확정했습니다.

## 제출물
- documents/QualityMate_기획서.pdf
- documents/QualityMate_결과보고서.pdf
- documents/QualityMate_최종발표.pptx
- source/ 전체 소스 코드와 검사 도구
- runtime/ Windows x64 자체 포함 실행 결과물
- samples/ VisionQC 원본 CSV 내보내기 코드로 생성한 가상 검사 파일
- evidence/ 기능 검사, RAG 20개 질문의 실제 답변·시간·근거

## 실행
압축을 모두 풀고 runtime/실행하기.cmd를 실행합니다.
기본 주소는 http://127.0.0.1:5187 입니다. 종료는 서버 창에서 Ctrl+C입니다.
Windows x64용 .NET 런타임이 포함되어 있어 앱 실행에 별도 SDK 설치는 필요하지 않습니다.
소스 빌드와 검사 도구 실행에는 .NET 10 SDK 및 PowerShell 7이 필요합니다.

## AI 준비
Ollama와 kanana2:3b 모델이 준비되어 있어야 AI가 동작합니다.
현재 개발 PC에서는 해당 모델을 확인하고 실제 답변을 검증했습니다.
모델 가중치는 포함하지 않습니다. 다른 PC에서는 Ollama를 공식 사이트에서 설치하고 모델 카드와 라이선스를 확인한 후 runtime/AI-setup.cmd를 실행하세요.
새 PC에서의 설치와 다운로드는 이 작업에서 수행하지 않았습니다.
AI 연결이 없으면 검색 원문을 표시하며 화면에 AI 연결 필요 상태를 알립니다.
현재 모델 설정은 runtime/appsettings.json에 있습니다.

공식 Ollama 설치 https://ollama.com/download/windows
GGUF 모델 카드 https://huggingface.co/mradermacher/kanana-2-3b-instruct-GGUF
원본 모델 https://huggingface.co/kakaocorp/kanana-2-3b-instruct
Ollama 모델 가져오기 https://docs.ollama.com/import

## 데이터와 시연
첫 실행에서는 가상 제품 3개와 표준서 4개 절을 제공합니다.
QM-001에서 재검사 절차 질문, 근거 확인, 재검사 저장을 시연합니다.
samples/VisionQC-demo.csv를 가져오면 3개 검사 행이 추가됩니다.
ERROR는 검사 오류로 유지되며 불량 유형을 임의로 추정하지 않습니다.
runtime/data/qualitymate.db에 저장합니다. 서버 종료 후 data 폴더를 백업하세요.
배포 폴더가 쓰기 가능한 위치에 있어야 합니다.

## 검증 결과
빌드와 JavaScript 문법 검사를 통과했습니다.
기능 검사 17개가 통과했습니다.
고정 질문 20개가 관련 근거·인용·원문 일치·필수 구절 포함 기준을 통과했습니다.
자체 포함 EXE를 별도 데이터·포트로 실행해 화면, 실제 AI, CSV 저장을 확인했습니다.
PPT 12장의 렌더링, 파일 구조, 글꼴, 차트 원본 데이터와 재가져오기 검사를 통과했습니다. 실제 PowerPoint 앱에서의 실행은 미검증입니다.
LLM 호출 16개 질문의 응답 중앙값은 2.98초, 전체 20개 최대는 4.03초였습니다.
실제 현장 정확도와 생산성 향상, 실제 카메라 추론, 다른 PC 운영을 검증한 결과는 아닙니다.
2026-11-20 브라우저 파일 선택과 가져오기 버튼으로 원본 샘플 재입력을 검증했습니다. 0건 추가·3건 중복 제외를 확인했습니다.

## 제출 전 확인 사항
프로젝트 형태는 개인으로 확정했습니다. 제출자 이름은 아직 전달받지 않아 기재하지 않았습니다. 교육기관 양식에 맞게 이름과 실제 수행 내용을 확인하세요.
documents의 Markdown 파일은 보고서와 기획서의 수정용 원문입니다.
현재 문서에는 확인되지 않은 이름이나 팀원 기여를 작성하지 않았습니다.
PPT의 발표자 노트에 설명과 시연 순서를 넣었습니다.
발표 PC에서는 AI 모델을 미리 준비하고 실제 시연을 연습해야 합니다.
개발 중 AI 코딩 도구를 활용했습니다. 면접과 발표를 위해 구조, 트랜잭션, RAG와 평가 기준을 직접 설명할 수 있도록 확인하세요.

## 구현 범위
설치 없는 로컬 시연을 위해 초기 SQL Server 계획을 SQLite로 조정했습니다.
실시간 카메라, 사용자 권한, 문서 업로드, 대규모 검색은 향후 개선 항목입니다.


## 발표 PC 준비와 복구
1. ZIP 전체를 Documents처럼 쓰기 가능한 폴더에 풉니다.
2. runtime/환경진단.cmd를 실행합니다. 별도 PowerShell 스크립트 설정이나 SDK가 필요하지 않습니다.
3. 종료 코드 0은 기본 환경 준비, 1은 파일·권한·설정·포트 문제, 2는 AI 준비가 필요하다는 뜻입니다. environment-check.json에 상세 결과가 저장됩니다.
4. AI 경고가 있으면 Ollama와 모델을 준비합니다. 모델 설치·다운로드는 진단 도구가 자동으로 하지 않습니다.
5. runtime/실행하기.cmd를 실행하고 AI 연결 상태를 확인합니다. 이미 QualityMate가 실행 중이면 기존 브라우저 페이지를 사용합니다.
6. 다른 PC로 옮긴 경우 그 PC에서 이 절차를 다시 수행합니다. 현재 PC의 통과 기록은 다른 PC의 검증 결과가 아닙니다.

### 5분 실행 시연
- 0:00 제품 목록과 최초·현재 판정의 구분을 설명합니다.
- 0:40 QM-001에서 “재검사에 필요한 기록은 무엇인가요?”를 질문합니다.
- 1:30 SOP-03 인용과 원문을 펼쳐 근거 선택형 RAG를 설명합니다.
- 2:10 검사자·조치 메모를 기록해 재검사를 저장하고 최초 기록이 유지됨을 확인합니다.
- 3:10 samples/VisionQC-demo.csv를 선택해 가져옵니다. 처음에는 3건 추가, 재입력은 3건 중복 제외가 정상입니다.
- 4:10 검사 오류와 불합격의 차이, 검증 범위와 한계를 설명합니다.

### 예상 질의응답
- 왜 SQLite인가요? 로컬 발표에서 서버 DB 설치 없이 트랜잭션과 이력 정합성을 재현하기 위해 선택했습니다.
- RAG에서 LLM 역할은? 검색된 원문 후보에서 근거 번호를 선택합니다. 서버가 범위를 검증하고 실제 원문을 표시합니다.
- 중복 저장을 어떻게 막나요? 재검사의 요청 ID와 이력 버전을 확인하고 트랜잭션 안에서 저장합니다.
- 20개 통과는 정확도 100%인가요? 아닙니다. 고정된 가상 질문에 대한 검색·인용·원문·필수 구절 기준의 통과 결과입니다.
- 카메라도 동작하나요? 이번 결과물은 검사 CSV를 연계합니다. 실시간 카메라 추론은 구현 범위 밖입니다.
- AI가 꺼져 있으면? AI 연결 필요 상태와 검색 원문을 표시합니다. 발표에서 이를 실제 LLM 응답으로 설명하지 않습니다.

환경 진단은 실행 파일에 내장되어 별도 PowerShell 실행 정책 변경이 필요하지 않습니다.
현재 PC의 정상 진단, 모델 누락 경고, 잘못된 설정 오류 3개 검사를 통과했습니다.
PowerPoint 앱 실행 자동화는 응답하지 않아 슬라이드 쇼 실검증은 완료하지 못했습니다. 파일·렌더링 검증 통과와 별도로 발표 PC에서 직접 열어 확인해야 합니다.
